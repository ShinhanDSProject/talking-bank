# Talking Bank 인프라 요구사항

> 상태: 초안(Draft)  
> 기준: `main` 브랜치에서 확인한 React/Vite 웹, Spring Boot API, H2 로컬 DB  
> 주의: 아래의 AWS 구성과 운영 목표는 제안이며 팀 합의 전에는 확정 사항이 아니다.

## 1. 목적

Talking Bank 서비스를 로컬, 개발, 운영 환경에서 반복 가능하고 안전하게 실행·배포한다. 금융 성격의 데이터를 다룰 가능성을 고려해 외부 노출 최소화, 비밀정보 분리, 감사 가능한 배포와 복구를 기본 원칙으로 삼는다.

## 2. 현재 확인된 구성

| 구분 | 현재 저장소에서 확인된 내용 |
| --- | --- |
| 웹 | React 19, TypeScript, Vite, 기본 포트 `5173` |
| API | Java 21, Spring Boot 3.5, Gradle, 기본 포트 `8080` |
| 데이터 | 로컬 H2 인메모리 DB |
| API 예시 | `GET /api/accounts` |
| 관측성 | Spring Boot Actuator 의존성 포함 |
| 미구현 | Docker, MariaDB, AWS, CI/CD, 운영 모니터링, 부하 테스트 |

## 3. 환경 구분

| 환경 | 목적 | 데이터 | 배포 방식 |
| --- | --- | --- | --- |
| `local` | 개인 개발 | H2 또는 Docker MariaDB의 가짜 데이터 | 개발자 PC에서 수동 실행 |
| `dev` | 팀 통합 검증 | 운영과 분리된 테스트 데이터 | `main` 병합 후 자동 배포 제안 |
| `prod` | 실제 서비스 | 운영 데이터 | 승인 후 배포 제안 |

환경별 DB, 비밀정보, 로그 저장소를 분리한다. 운영 데이터를 개발 환경으로 복사하지 않는다.

## 4. 기능 요구사항

- 사용자는 HTTPS로 웹에 접속한다.
- 웹은 `/api` 경로로 Spring Boot API를 호출한다.
- API는 회원, 계좌, 인증 및 향후 거래 데이터를 영구 DB에 저장한다.
- 애플리케이션 설정은 환경 변수 또는 비밀정보 저장소에서 주입한다.
- 배포 후 자동 상태 확인을 수행한다.

## 5. 비기능 요구사항 초안

`비기능 요구사항`은 화면 기능이 아니라 성능, 안정성, 보안, 운영 편의성처럼 서비스 품질을 규정한다.

| 항목 | 개발 환경 목표 | 운영 목표 초안 | 확정 필요 |
| --- | --- | --- | --- |
| 가용성 | 업무 시간 내 테스트 가능 | 다중 AZ와 API 2개 이상 검토 | 목표 가동률 |
| 성능 | 기능 검증 우선 | 주요 조회 API p95 500ms 이하 제안 | 실제 사용자 수 |
| 오류율 | 테스트 실패 확인 | 정상 트래픽 기준 1% 미만 제안 | API별 기준 |
| 확장성 | 최소 사양 | ECS Task 수평 확장 제안 | 최대 RPS |
| 보안 | 가짜 데이터만 사용 | HTTPS, 비공개 DB, 비밀정보 분리 | 규제 범위 |
| 복구 | 재생성 가능 | RDS 자동 백업과 복원 훈련 | RPO/RTO |

## 6. 보안 요구사항

- DB와 API 컨테이너를 인터넷에 직접 공개하지 않는다.
- 외부 통신은 HTTPS를 사용한다.
- 비밀번호, JWT 비밀키, 접근 키를 Git에 저장하지 않는다.
- 계좌번호, 토큰, 비밀번호를 로그에 기록하지 않는다.
- IAM 권한은 업무에 필요한 최소 범위만 부여한다.
- 운영 변경과 배포 이력을 추적할 수 있어야 한다.
- 운영 DB에는 암호화와 자동 백업을 적용한다.

## 7. 배포 요구사항

- Pull Request에서 백엔드 테스트, 프론트 테스트, lint, typecheck, build를 수행한다.
- 실패한 검증 결과물은 배포하지 않는다.
- 동일한 소스 버전으로 다시 배포할 수 있어야 한다.
- 배포 실패 시 직전 정상 버전으로 되돌릴 수 있어야 한다.
- DB 변경은 Flyway 등 버전형 마이그레이션 도구로 관리한다.

## 8. 모니터링 요구사항

- ALB 요청 수, 응답시간, HTTP 4xx/5xx를 수집한다.
- ECS CPU, 메모리, 실행 Task 수를 수집한다.
- JVM 및 애플리케이션 오류를 수집한다.
- RDS CPU, 저장공간, 연결 수, 지연시간을 수집한다.
- 알람의 기준, 수신자, 조치 방법을 문서화한다.

## 9. 팀 결정이 필요한 질문

- AWS 계정과 담당자는 누구인가?
- 서울 리전(`ap-northeast-2`)을 사용할 것인가?
- 월 인프라 예산 상한은 얼마인가?
- 예상 동시 사용자, 평균 RPS, 최대 RPS는 얼마인가?
- 실제 개인정보와 금융정보를 저장하는가?
- 목표 가동률, RPO, RTO는 얼마인가?
- `dev`와 `prod`를 별도 AWS 계정으로 분리할 것인가?
- 운영 배포 승인자는 누구인가?

## 10. 완료 조건
