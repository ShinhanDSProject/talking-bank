# talking-bank MVP

> 상태: 팀 검토용 초안 · 개발 기간: 4주
>
> 지금까지 합의한 구현 범위와 완료 기준을 정리한다. 세부 사용자 흐름과 업무 규칙은 후속 PRD에서, 데이터 구조와 제약은 후속 ERD에서 구체화한다.

## 1. 목표

계좌 잔액을 확인하거나 이체하기 위해 여러 메뉴를 직접 찾아야 하는 번거로움을 줄인다. 기존 인터넷뱅킹 기능을 PC 웹으로 제공하면서, 음성·텍스트 AI 챗봇으로도 조회·송금 요청·소비 분석을 이용할 수 있게 한다.

핵심 원칙은 **말하면 알아듣고, 돈은 사람이 확인해야 움직이는 은행**이다. AI가 송금 내용을 구성하더라도 사용자의 최종 확인과 6자리 간편 비밀번호 검증을 거친 뒤 실행한다.

## 2. 팀과 개발 기간

| 역할 | 담당자 |
| --- | --- |
| PM | 조성민 |
| AI | 김민석 |
| 백엔드 | 전민욱, 남윤재 |
| 프론트엔드 | 김예은, 이해진 |

총 6명이 4주 동안 개발한다.

## 3. 서비스와 화면 방향

- PC 인터넷뱅킹 중심의 웹 서비스로 구성한다. 계좌 조회·이체 등을 일반 메뉴와 화면에서 사용할 수 있다.
- AI 챗봇은 일반 은행 화면과 함께 제공한다. 챗봇의 정확한 위치와 크기는 화면 설계 단계에서 결정한다.
- 음성은 STT로 텍스트로 변환하며, 직접 입력한 텍스트와 동일한 챗봇 기능을 이용한다.
- 응답은 텍스트·거래 내역·차트 등 화면으로 제공하며 음성으로 읽어주지 않는다.
- 농협·국민·경남 등 실제 은행 이름을 활용하되, 프로젝트 내부에서 운영하는 가상 은행으로 시연한다.
- 모든 계좌·잔액·결제·이체는 가상 데이터로 처리한다. 실제 은행이나 실제 자금과 연동하지 않는다.

## 4. MVP 포함 범위

### 4.1 회원가입과 로그인

- 이메일·비밀번호 회원가입 및 로그인
- 카카오·구글 소셜 로그인
- 하나의 사용자 계정에 여러 로그인 수단 연결
  - 이메일 또는 소셜 로그인 중 하나로 처음 가입한다.
  - 기존 계정에 로그인한 상태에서 다른 로그인 수단을 인증하고 연결한다.
  - 연결된 어떤 수단으로 로그인하든 동일한 계좌와 데이터를 이용한다.
  - 이메일 주소가 같다는 이유만으로 계정을 자동 병합하지 않는다.
- 송금용 6자리 간편 비밀번호 설정 및 검증
  - 소셜 로그인 가입자도 송금을 위해 별도로 설정한다.

### 4.2 가상 은행과 계좌

- 가입 후 사용자가 은행을 선택해 가상 계좌 개설
- 한 사용자의 여러 은행 계좌 보유
- 새 계좌의 초기 잔액: 계좌당 100만 원
- 초기 샘플 소비 내역 제공
  - 과거 입출금 기록과 최종 잔액이 일치하도록 구성한다.
- 본인 계좌의 가상 돈 충전 및 입금 내역 기록
- 계좌 목록·잔액·거래 내역 조회

### 4.3 송금

- 같은 은행 및 다른 가상 은행으로 이체
- 본인 계좌 간 이체
- 다른 가입자와 시연용 가상 인물의 계좌로 이체
- 송금 실행 시 출금·입금 계좌의 잔액과 거래 내역 반영
- 일반 송금 화면과 음성·텍스트 챗봇에서 송금 요청
- 받는 사람·은행·계좌·금액·출금 계좌를 최종 확인하고, 6자리 간편 비밀번호 검증 후 실행
- 자주 보내는 계좌 등록 및 사용자별 별명 지정
- 기본 출금 계좌 지정
  - 요청에서 특정 계좌를 지정하면 해당 계좌를 우선 사용한다.
  - 최종 확인 화면에서도 출금 계좌를 확인하고 변경할 수 있다.

### 4.4 가상 결제와 소비 분석

- 사용자가 이용하는 별도의 가상 결제 화면
- 가맹점과 금액을 선택해 결제하고, 계좌 잔액과 거래 내역에 반영
- 가맹점 업종에 따른 소비 카테고리 자동 분류
- 사용자가 개별 거래의 카테고리를 지정하거나 수정
- 샘플 거래와 새로 발생한 거래를 함께 분석
- 음성·텍스트로 기간·카테고리별 소비 금액과 내역 조회
- 기간별 소비 비교, 증감액·증감률 및 차트 제공
- 카테고리 변경 결과를 소비 통계와 차트에 반영

| 거래 종류 | 소비 집계 | 분류 방식 |
| --- | --- | --- |
| 가맹점 결제 | 포함 | 가맹점 업종에 따라 자동 분류, 사용자 수정 가능 |
| 다른 사람에게 송금 | 포함 | 최초에는 미분류, 사용자가 직접 지정 가능 |
| 본인 계좌 간 이체 | 제외 | 본인 자금 이동 |
| 가상 돈 충전 | 제외 | 입금 |

사용자의 분류 변경은 해당 거래에만 적용한다. 가맹점 기본 분류, 실제 거래 금액, 계좌 잔액은 변경하지 않는다. 미분류 송금도 전체 소비 합계에는 포함한다.

### 4.5 AI 챗봇과 대화 관리

- 음성·텍스트 입력을 통한 잔액·거래 조회, 송금 요청, 소비 분석
- 앞선 대화를 이어받아 누락된 정보를 추가 질문
  - 예: “엄마한테 돈 보내줘” → “얼마를 보낼까요?” → “5만 원” → 송금 확인 화면
- 대화 내역 저장·다시 보기·새 대화 시작·삭제
- 대화 삭제와 금융 거래 기록을 분리하여, 대화를 삭제해도 송금·결제 기록은 유지

### 4.6 관리자

일반 사용자 화면과 구분된 관리자 페이지를 제공하고, 관리자 권한이 있는 계정만 접근할 수 있게 한다.

| 기능 | 범위 |
| --- | --- |
| 사용자 조회 | 가입 사용자와 계정 상태 확인 |
| 계좌·거래 조회 | 가상 계좌 및 송금·결제·충전 내역 확인 |
| 가맹점 관리 | 가맹점 등록, 업종·소비 카테고리 설정 |
| 시연 데이터 관리 | 가상 인물·계좌 생성, 샘플 거래 내역 추가 |

## 5. 제외 및 미정 항목

| 항목 | 상태 |
| --- | --- |
| 금융상품 조회·가입 | 전체 서비스의 확장 요구사항으로 남기고 MVP에서는 제외 |
| 패스키 로그인 | 미정, 현재 MVP 완료 기준에는 포함하지 않음 |
| 얼굴·지문 인증 별도 구현 | 이번 범위에서 제외 |
| 음성 응답(TTS) | 제외 |
| 실제 은행 연동 및 실제 자금 이체 | 제외 |

은행 서비스의 모든 기능을 구현하는 것을 MVP 목표로 삼지 않는다. 위에 명시되지 않은 기능은 자동으로 포함하지 않고 별도 합의한다.

## 6. 핵심 시연 흐름

### 시연 A: 로그인부터 음성 송금까지

1. 회원가입 또는 로그인한다.
2. 은행을 선택해 가상 계좌를 개설하고 초기 잔액과 샘플 거래를 확인한다.
3. 송금용 간편 비밀번호, 자주 보내는 계좌의 별명과 기본 출금 계좌를 설정한다.
4. “엄마에게 돈 보내줘”라고 말한다.
5. 챗봇의 금액 질문에 “5만 원”이라고 답한다.
6. 출금 계좌·받는 사람·은행·계좌·금액을 확인하고 6자리 간편 비밀번호를 입력한다.
7. 송금 완료와 양쪽 계좌의 잔액·거래 내역 반영을 확인한다.

### 시연 B: 결제부터 소비 분석까지

1. 가상 결제 화면에서 식당을 선택해 결제한다.
2. “이번 달 식비 얼마 썼어?”라고 음성 또는 텍스트로 묻는다.
3. 샘플 내역과 방금 결제한 내역을 포함한 합계·상세 내역을 확인한다.
4. “지난달과 비교해줘”라고 요청해 비교 금액과 차트를 확인한다.
5. 미분류 송금을 식비로 지정하거나 자동 분류된 결제의 카테고리를 변경한다.
6. 변경된 소비 분석 결과를 확인한다.

## 7. MVP 완료 기준

아래 기준은 요구사항 검증을 위한 기준이며, 구체적인 예외 처리와 수치는 PRD에서 정한다.

- 핵심 시연 A·B가 실제 가상 데이터의 저장·조회·변경을 통해 끝까지 동작한다.
- 이메일·카카오·구글 로그인과 로그인 수단 연결 후 동일 사용자 데이터 접근이 가능하다.
- 일반 화면에서도 계좌 조회·거래 조회·송금이 가능하다.
- 여러 가상 은행의 계좌 개설과 본인·타인·타행 이체가 가능하다.
- 사용자 확인과 간편 비밀번호 검증 없이 송금이 실행되지 않는다.
- 성공한 이체는 양쪽 계좌에 함께 반영되며, 실패하거나 중복 요청된 이체로 돈이 잘못 차감되지 않는다.
- 초기 데이터·충전·결제·송금의 잔액과 거래 내역이 일치한다.
- 소비 합계와 카테고리별 통계가 4.4절의 집계 기준을 따른다.
- 대화 관리와 관리자 기능이 포함 범위대로 동작하고, 일반 사용자는 관리자 기능을 사용할 수 없다.

## 8. 후속 문서 작업

1. MVP 이슈·PR에서 범위와 완료 기준을 팀이 검토한다.
2. 별도 PRD 이슈·브랜치·PR에서 세부 흐름과 업무 규칙을 정한다.
3. 별도 ERD 이슈·브랜치·PR에서 데이터 구조와 제약을 설계한다.

4주 일정에서는 핵심 시연 흐름의 통합 동작을 우선한다. 나머지 포함 기능도 MVP 범위이며, 일정상 조정이 필요하면 팀 합의로 이 문서를 변경한다.

기존 `DESIGN.md`의 화면 토큰은 활용하되, 인증서 로그인·AI 도입 단계·관리자 메뉴·음성 되읽기 등 이전 기획과 다른 내용은 후속 화면 설계에서 정합성을 맞춘다. 해당 항목을 이번 MVP의 추가 요구사항으로 간주하지 않는다.
