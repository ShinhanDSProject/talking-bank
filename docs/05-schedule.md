# 05. 진행 순서

> 이 문서는 **날짜를 적지 않는다.** Phase의 순서와 원칙, 전체 시연 시나리오, 리스크만 다룬다. 각 Phase 안의 Step과 완료 조건은 [`domains/`](domains/) 아래 도메인 문서에 있다. 날짜는 팀 회의에서 정해 GitHub 마일스톤에 붙인다.

## 원칙

1. **Phase는 순서대로, 하나씩.** 앞 Phase의 완료 조건을 만족하기 전에 다음 Phase를 시작하지 않는다.
2. **Phase 1의 첫 Step에서 끝까지 관통하는 한 줄을 만든다.** 가장 먼저 로그인 → API → 화면 → 배포가 작게라도 한 번 돌아가게 하고, 그 뒤에 기능을 얹는다.
3. **완료 조건은 "누가 봐도 확인 가능한 것"으로 쓴다.** "송금 구현"이 아니라 "동시성 테스트가 통과한다".
4. **Step을 놓치면 다음 Step에서 뺀다. 밀지 않는다.**
5. **발표 전 마지막 Step은 항상 "마무리"다.** 새 기능을 넣지 않고, 시연 시나리오를 반복해 돌리며 버그만 잡는다.

## Phase 진행

각 Phase는 같은 모양이다: **진입 조건 → 설계 → 구현 → 안정화 → 완료 조건.** 상세는 도메인 문서를 본다.

| Phase | 도메인         | 진입 조건    | 완료 조건 (요약)                                                              | 문서                                                   |
| ----- | -------------- | ------------ | ----------------------------------------------------------------------------- | ------------------------------------------------------ |
| 1     | 은행 코어      | —            | 배포 주소에서 가입 → 로그인 → 송금 → 거래내역. 동시성·롤백·멱등성 테스트 통과 | [domains/01-core.md](domains/01-core.md)               |
| 2     | 리스크 (FDS)   | Phase 1 완료 | 고액 송금이 보류되고 추가 인증 후 완료된다. 차단 건이 관리자 화면에 뜬다      | [domains/02-risk.md](domains/02-risk.md)               |
| 3     | 여신/수신 상품 | Phase 2 완료 | 적금 자동 납입 배치가 돌고, 만기 시 이자 포함 지급이 거래내역에 남는다        | [domains/03-product.md](domains/03-product.md)         |
| 4     | 오픈뱅킹       | Phase 1 완료 | 가상 외부 앱이 OAuth로 동의를 받아 계좌를 조회하고 이체한다                   | [domains/04-openbanking.md](domains/04-openbanking.md) |
| 5     | 카드           | Phase 3 완료 | 결제 승인이 계좌 잔액을 줄이고, 일마감 배치가 가맹점별 정산액을 만든다        | [domains/05-card.md](domains/05-card.md)               |
| 6     | 증권           | Phase 3 완료 | 매수 체결 2영업일 뒤 결제 배치가 돌고, 평가액이 갱신된다                      | [domains/06-securities.md](domains/06-securities.md)   |
| 7     | 보험           | Phase 3 완료 | 보험료 미납 시 실효 배치가 돌고, 부활 시 미납분이 정산된다                    | [domains/07-insurance.md](domains/07-insurance.md)     |

- Phase 4(오픈뱅킹)는 배치 의존이 없어 Phase 1 뒤 어디에 두어도 된다.
- Phase 5~7은 서로 독립이라 순서를 바꿔도 된다. 단, 전부 Phase 3의 배치 인프라를 쓴다.
- **동시에 두 Phase를 진행하지 않는다.**
- Phase 1이 프로젝트의 마지막 Phase라면 그 마지막 Step이 발표 전 마무리다(발표 자료·데모 영상 백업 포함). Phase 2 이상을 진행한다면 마무리 Step은 마지막 Phase 끝에 둔다.

## 시연 시나리오

Phase 1의 송금이 동작하는 시점부터 이 순서대로 매일 한 번 돌려본다. 완료한 Phase마다 장면을 덧붙인다.

**Phase 1**

1. 회원가입 → 로그인
2. 내 계좌와 잔액 확인
3. 다른 회원에게 송금 → 성공 → 양쪽 거래내역 확인
4. 잔액보다 큰 금액 송금 → 거절
5. 같은 송금 버튼 연타 → 한 번만 이체됨

**Phase 2**

6. 고액 송금 → FDS 보류 → 추가 인증 → 완료
7. 단시간 반복 송금 → 차단
8. 관리자 로그인 → 이상거래 목록에서 6·7번 확인 → 거래 로그

**Phase 3 이후** — 각 도메인 문서의 "시연 장면"을 덧붙인다. 예: 적금 가입 → (배치 실행) → 납입 내역이 거래내역에 찍힘.
