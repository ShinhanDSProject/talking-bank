# 01. 프로젝트 개요

## 한 줄 정의

**하나의 은행 계좌를 중심으로 6개 금융 도메인이 연결된 시스템** — 은행 코어(인증·계좌·이체·거래)를 먼저 깊게 만들고, 그 위에 리스크(FDS), 여신/수신 상품, 오픈뱅킹, 카드, 증권, 보험을 단계적으로 쌓는다.

## 배경

| 도메인                | 핵심                                    |
| --------------------- | --------------------------------------- |
| 은행 여신/수신        | 계좌 · 이체 · 예금 · 대출 · 이자 · 연체 |
| 리스크 & 컴플라이언스 | FDS · AML · 이상거래 탐지               |
| 핀테크 & 오픈뱅킹     | OAuth · 오픈 API · 마이데이터 · 토큰화  |
| 카드 결제/정산        | 승인 · 매입 · 정산 · 청구 사이클        |
| 증권/투자             | 주문 · 체결 · T+2 결제 · 포트폴리오     |
| 보험                  | 보험료 · 언더라이팅 · 만기 · 실효/부활  |

이 6개는 따로 노는 시스템이 아니다. **전부 은행 계좌에 연결되어 있다.** FDS는 계좌에서 나가는 모든 거래를 감시하고, 카드 결제는 계좌에서 출금되고, 증권 매수 대금은 계좌에서 빠지고, 보험료는 계좌에서 자동이체되고, 오픈뱅킹은 그 계좌를 외부 앱에 노출한다.

그래서 프로젝트를 이렇게 잡는다.

```
                    ┌─ 리스크 (FDS)     계좌에서 나가는 모든 거래를 감시한다
                    ├─ 여신/수신 상품   예금·대출이 계좌에 붙는다
은행 코어 ──────────┼─ 오픈뱅킹        계좌 조회·이체 API를 OAuth로 외부에 연다
인증 · 계좌 · 이체  ├─ 카드            체크카드 승인 → 계좌 출금 → 가맹점 정산
· 거래내역          ├─ 증권            계좌 연동 매수 → T+2 결제
                    └─ 보험            보험료 자동이체 → 만기 처리
```

**은행 코어를 Phase 1로 먼저 만들고, 6개 도메인을 Phase 2 이후에 하나씩 얹는다.** 각 도메인은 코어와 연결되는 핵심 흐름 하나씩만 구현하고, 어느 Phase에서 멈춰도 동작하는 결과물이 남는다. Phase 순서와 범위는 [02-scope.md](02-scope.md), 진행 순서는 [05-schedule.md](05-schedule.md)에 있다.
