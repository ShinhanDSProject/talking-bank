# 01. 프로젝트 개요

## 한 줄 정의

**말하면 알아듣고, 돈은 사람이 확인해야 움직이는 은행** — 은행 코어(인증·계좌·이체·거래)를 먼저 깊게 만들고, 그 위에 자연어로 조회·이체 초안을 만드는 AI 비서와 FDS 규칙을 얹는다.

## 배경

은행 앱은 메뉴가 깊다. "엄마한테 5만원"을 보내려면 이체 메뉴 → 출금계좌 → 은행 선택 → 계좌번호 → 금액 → 확인까지 여섯 화면을 지난다. 시니어와 시각장애인에게는 벽이고, 익숙한 사람에게도 귀찮다. 그렇다고 AI에게 돈을 맡기면 오인식 한 번이 사고가 된다.

이 프로젝트는 그 사이를 잡는다.

| 누가          | 하는 일                                                                             | 하지 않는 일               |
| ------------- | ----------------------------------------------------------------------------------- | -------------------------- |
| **AI 비서**   | 말을 알아듣고, 잔액·거래내역을 읽고, 수취인을 찾고, 이체 **초안**을 만든다          | 이체를 **실행**하지 않는다 |
| **사람**      | 채워진 확인 화면을 보고 이체 비밀번호로 실행한다                                    |                            |
| **은행 코어** | 트랜잭션·잠금·멱등성으로 돈을 정확히 옮기고, FDS 규칙으로 고액·반복 이체를 보류한다 |                            |

AI는 돈을 움직일 **수단이 없다.** 도구 목록에 실행이 없고, 실행 API는 이체 비밀번호가 필수이며, AI 서비스의 토큰은 읽기·초안 스코프뿐이다. 이 세 겹이 프로젝트의 중심 설계다.

```
                              ┌─ 조회      "잔액 얼마야?" "지난달 배달에 얼마 썼어?"
사용자 ── 말 ──▶ AI 비서 ─────┼─ 초안      "엄마한테 5만원" → 확인 화면이 채워져 열린다
                              └─ 설명      "왜 막혔어?"  → FDS 보류 사유를 쉬운 말로
                                   │ 읽기 · 초안 스코프
                                   ▼
                              은행 코어  ── 이체 실행은 사람의 확인 + 이체 비밀번호로만
                              인증 · 계좌 · 이체 · 거래내역 · FDS 규칙
```

**은행 코어를 Phase 1로 먼저 만들고, 대화형 뱅킹을 Phase 2로 얹는다.** 어느 Phase에서 멈춰도 동작하는 결과물이 남는다. Phase 범위는 [02-scope.md](02-scope.md), 진행 순서는 [05-schedule.md](05-schedule.md)에 있다. 리스크 전체·상품·오픈뱅킹·카드·증권·보험은 **향후 확장 후보**로 문서만 남긴다.
